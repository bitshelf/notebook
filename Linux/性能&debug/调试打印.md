# Linux 调试打印
## 内核源码打印
```c
printk(KERN_EMERG"string":%s,%d",__func__,__LINE__);
```
- `trace_printk`使用方法和printk一样，它输出的信息会写入ftrace的循环缓存中（ring buffer），即相当于写内存，速度比写串口等硬件设备要快好几个数量级

## 控制台打印
```shell
/proc/sys/kernel/printk
echo 8 > /proc/sys/kernel/printk
```
- `/proc/sys/kernel/printk` 包含了 4 个整数值：
	1. 当前的日志级别
	2. 默认的消息级别
	3. 最小的允许的日志级别
	4. 引导时的默认日志级别
- 向该文件写入**单个**整数值，将会改变当前的日志级别这个值

## syslogd
- syslogd 默认使用/etc/syslog. conf 作为配置文件，负责截获应用程序消息，还可以截获 klogd 向其转发的内核消息
- Syslog 是一个通过 IP 网络允许一台机器发送事件通知信息给事件收集者（Syslog 服务器或者 Syslog Daemon）的协议
- 完整的syslog日志中包含产生日志的程序模块（Facility）、严重性（Severity或 Level）、时间、主机名或IP、进程名、进程ID和正文
- syslogd 是一个分发器，它将接收到的所有日志按照/etc/syslog. conf 的配置策略发送到这些日志应该去的地方，当然也包括从 klogd 接收到的日志。klogd 首先接收内核的日志，然后将之发送给 syslog
- syslogd 日志记录器由两个守护进程（klogd，syslogd）和一个配置文件（syslog. conf）组成
- 支持 internet/unix domain sockets 的特性使得这两个工具可以用于记录本地和远程的日志
- 接收syslog的服务器可以对多个设备的syslog消息进行统一的存储，或者解析其中的内容做相应的处理

### klogd
- klogd 是很有意思的守护进程
- klogd 首先接收内核的日志，然后将之发送给 syslog
- - klogd 不使用配置文件，它负责截获内核消息，它既可以独立使用也可以作为 syslogd 的客户端运行
