# 窗口显示专题

窗口显示主要是 App 与 WMS 的交互，WMS 本身可以分为三个部分：

* WindowContainor 树
* WMS 大遍历（performSurfacePlacement）就是对当前所有存在的 Window 进行窗口大小计算和窗口绘制状态更新，最后把窗口 Surface 更新到 Surfaceflinger。
* 本地窗口动画

窗口的显示会涉及到这三个部分，是学习 WMS 的切入点。三点必须熟练掌握。

## 1. 窗口如何显示

App 端窗口显示有两种方式：

* 启动一个 Activity
* 添加一个悬浮窗/系统窗口

第一种，启动一个 Activity，代码如下：

```java
// 启动 Activity
ComponentName cn = new ComponentName("当前Activity的全类名","启动Activity的全类名") ;
Intent intent = new Intent();
intent.setComponent(cn);
startActivity(intent);

// 还有很多其他方式启动 Activity，如果做过 App，应该非常熟悉，就不在列举了
```

第二种，添加悬浮窗（需要悬浮窗的运行时权限）：

```java
        private WindowManager mWindowManager;
        private WindowManager.LayoutParams mLayoutParams;

        // 准备工作
        // 取得系统窗体
        mWindowManager = (WindowManager)getSystemService(Context.WINDOW_SERVICE);

        // 窗体的布局样式
        mLayoutParams = new WindowManager.LayoutParams();

        // 设置窗体显示类型——TYPE_APPLICATION_OVERLAY
        mLayoutParams.type = WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY;
        mLayoutParams.flags = WindowManager.LayoutParams.FLAG_NOT_TOUCH_MODAL;

        // 设置显示的模式
        mLayoutParams.format = PixelFormat.RGBA_8888;

        // 设置对齐的方法
        mLayoutParams.gravity = Gravity.TOP | Gravity.LEFT;

        // 设置窗体宽度和高度
        mLayoutParams.width = WindowManager.LayoutParams.WRAP_CONTENT;
        mLayoutParams.height = WindowManager.LayoutParams.WRAP_CONTENT;

        mLayoutParams.x = 550;
        mLayoutParams.y = 550;

        //窗口设置动画
        mLayoutParams.windowAnimations = R.style.MyWindow;
        //设置窗口名字
        mLayoutParams.setTitle("test-window");

        // 显示/隐藏窗口

        //一般， mView 是一个自定义 View;
        XxxView mView;
        // 省略 mView 的初始化过程
        // 显示悬浮窗
        mWindowManager.addView(mView, mLayoutParams);
        // 隐藏悬浮窗
        mWindowManager.removeView(mView);
```

主要要点：

1. WMS 中使用 WindowContainor 树来描述整个显示结构，需要掌握相关数据结构，确保自己能描述各个类的作用
2. WindowContainor 树的初始化过程
3. SurfaceFlinger 中，Layer 树的初始化过程
4. 能根据 `adb shell dumpsys activity containers` 的信息绘制出 WindowContainor 树

WindowContainor 树结构：

对于 Activity 窗口，从下往上是：WindowState，ActivityRecord，Task，TaskDispalyArea，DisplayArea，DisplayContent

对于系统窗口/悬浮窗，从下往上是：WindowState，WindowToken，DisplayArea.Tokens，DisplayArea，DisplayContent


WindowContainor 树的初始化过程：

1. 初始化好 Feature 集合
2. 利用 Feature 集合构建一个 PendingArea 树
3. 利用 PendingArea 树构建出最终的 WindowContainor 树
4. 在 Activity 添加的过程中去添加 Task ActivityRecord WindowState 节点，在系统窗口/悬浮窗添加过程中，去添加 WindowState WindowToken


Layer 树的初始化过程：

1. DisplayContent 在初始化时，会构建对应的 SurfaceControl 对象，SurfaceControl 对象在初始化时会发起远程调用，在 SurfaceFlinger 中构建对应的 Layer 对象
2. WindowContainor 树其他节点在调用 `WindowContainer::addChild` 方法挂在进树时，会创建对应的 SurfaceControl 对象，同时在 SurfaceFlinger 中构建对应的 Layer 对象，并设置好对应的父子关系，这样 Layer 树就构建起来了。

简单总结一下：

1. app 构建好根 View，LayoutParams
2. App 远程调用到 WMS，addToDisplayAsUser，主要是构造 WindowState，并挂载到容器树，同时初始化 SurrfaceControl，构建 layer，挂载到 Layer 树
3. App 端，预测量窗口大小
4. Choreographer#postCallback 申请 Vsync-app 信号，注册 Vsync 回调 mTraversalRunnable
5. Vsync-app 信号到达，回调 mTraversalRunnable#run 方法
   1. 利用前面预测的窗口尺寸，预测量根 View 的大小
   2. App 端远程调用到 WMS#relayoutWindow 方法：
      1. 添加 SurfaceControl/Layer，添加用于绘制的 Layer，WindowState 挂载到容器树时也添加了一个 Layer，一个 WindowState 就对应了两个 Layer
      2. WMS 会走一次大遍历，主要工作是测量窗口大小
      3. 向 App 返回测量的信息
   3. App 端初始化 BlastBufferQueue
6. App 端，View 树的 measure layout draw，其中 draw 过程分为了软件绘制和硬件绘制
7. App 远程调用到 WMS#finishDrawingWindow，WMS 会走一次大遍历，主要是修改相应的状态位，通过 SurfaceControl#Transaction 通知 sf 可以显示窗口了，以及播放窗口打开的过渡动画

这部分最重要的是大遍历（performSurfacePlacement）的源码，可以参考：

* https://blog.csdn.net/u012627628/article/details/135777102
* https://www.jianshu.com/p/b415c02b9976


在窗口的显示过程中会多次执行到 WMS 的大遍历过程（performSurfacePlacement），和显示相关的主要是：

* App 远程调用 `Session#relayout`时，这个阶段 performSurfacePlacement 中主要完成：
  * 测量窗口尺寸，代码里面叫 compute(计算)，实际更多是判断，主要是考虑刘海屏，系统窗口（inset），输入法等对系统窗口的影响，但是起决定性作用的还是 App 端传入的 `WindowManager#LayoutParam` 参数，计算完成后会返回信息给 App
  * 测量完成后会通过 `RootWindowContainer#applySurfaceChangesTransaction` 方法，将窗口的变化通过 SurfaceControl#Transition 提交给 SurfaceFlinger
* App 绘制完成后，远程调用到 `performSurfacePlacement`，这个阶段 performSurfacePlacement 中主要完成：
  * 窗口的同步判断，如果一个界面存在多个窗口，需要多个窗口均绘制完成后，才能通过 Transition 提交 show 事务
  * 窗口动画的执行，窗口的进入通常都伴随窗口动画的执行


Surface 同步机制：

在 Android13 中增加了 Surface 同步机制，主要作用是提供 ViewRootImpl、SurfaceView 和 SurfaceControlViewHost 的渲染同步服务。具体的，在 ViewRootImpl、SurfaceView 和 SurfaceControlViewHost 均完成绘制时再去上报至 WMS 进行窗口状态的切换。避免 ViewRootImpl 绘制完成上报至 WMS 后、同时 SurfaceView/SurfaceControlViewHost 迟迟没有绘制完成使得 startingWindow 过早移除从而产生黑屏/闪屏的现象。

* 每一个 ViewRootImpl/SurfaceView/SurfaceControlViewHost 对象会有一个对应的 SurfaceSyncGroup 对象。
* 每一个 SurfaceSyncGroup 对象都有一个 mTransactionReadyConsumer 回调，当对应的 ViewRootImpl/SurfaceView/SurfaceControlViewHost 绘制完成后，会调用到该回调
* 多个 SurfaceSyncGroup 通过树结构组织起来，通过成员 `ISurfaceSyncGroup mParentSyncGroup;` 可以找到其父节点。ViewRootImpl 中有一个 `mWmsRequestSyncGroup` 成员是这颗树的根节点
* 当 SurfaceSyncGroup 节点 A 添加一个子节点 B 时，会将子节点 B 的 `ISurfaceSyncGroup mParentSyncGroup;` 成员指向父节点 A 的 `ISurfaceSyncGroup mISurfaceSyncGroup` 成员，mISurfaceSyncGroup 有一个隐式的 this 引用指向 SurfaceSyncGroup 节点 A 
* 当 SurfaceSyncGroup 节点 A 添加一个子节点 B 时
  * 会将节点 A 的 `Consumer<Transaction> mTransactionReadyConsumer;` 包装成一个 ITransactionReadyCallback 对象，添加到节点 A 的`ArraySet<ITransactionReadyCallback> mPendingSyncs` 成员中。
  * 同时将该 ITransactionReadyCallback 对象发送给节点 B，节点 B 重新构造自己的 `Consumer<Transaction> mTransactionReadyConsumer;`
  * 当节点 B 对应的 Surface 绘制完后后，就会调用重新构造的 `Consumer<Transaction> mTransactionReadyConsumer;` 回调，在该回调中，先调用节点 B 自己原来的 mTransactionReadyConsumer 回调，再调用父节点 A 传过来的 ITransactionReadyCallback，同时将 ITransactionReadyCallback 从父节点 A 的 mPendingSyncs 成员中删除
* 只有 A 节点中的 mPendingSyncs 为空时，A 节点的子节点们才算都绘制完成了。

7. View#invalidate 和 View#requestLayout 的区别是什么？

* invalidate 和 requestlayout 都会调用到 ViewRootImpl#performTraversals，刷新页面。
* invalidate 通过设置当前 View 的 mPrivateFlags，实现了在 performTraversals 中不执行 measure 和 layout 过程，只执行 draw 过程，draw 过程只更新调用方 View 对应的 DisplayList 数据。
* requestLayout 通过设置当前 View 及其父级View 的 mPrivateFlags，实现了在 performTraversals 中只执行调用方 View 及其所有父级 View 的 measure 和 layout 过程。通常不执行 draw 过程。如果 View 在 layout 过程发现 View 的位置变化，会调用 invalide 执行 View 的 draw 过程。



8. 为什么 View 刚被加载时想获取其的宽高,需要 view.post(Runnalbe) 中获取

因为 View 刚初始化时，还没有完成宽高的测量。

View 测量的时机是：窗口显示时（Activity onResume 回调之后）会调用 ViewRootImpl#setView 方法，在该方法中会去 post 一个 runnable 到主线程执行，这个 runnable 中会调用 performTraversals 方法测量 View 大小。

ViewRootImpl 是否已经创建，View.post() 会执行不同的逻辑。如果 ViewRootImpl 已经创建，即 mAttachInfo 已经初始化，直接通过 Handler 发送消息来执行任务。如果 ViewRootImpl 未创建，即 View 尚未开始绘制，会将任务保存为 HandlerAction，暂存在队列 HandlerActionQueue 中，等到 View 开始绘制，执行 performTraversal() 方法时，在 dispatchAttachedToWindow() 方法中通过 Handler 分发 HandlerActionQueue 中暂存的任务，这些任务会在 performTraversal 中测量相关工作完成后执行。


9. 黄油计划提出的 Vsync 和三缓冲机制为什可以大大改善 Android 的交互和流畅度体验？

Vsync 机制主要用于处理 App 中图层的绘制，SF 中图层的合成，以及屏幕的刷新显示节奏的不一致导致的画面撕裂问题。

在 Android12 中，显示 buffer 的申请和提交已从 SF 端转移到了 App 端。App 绘制，SF 合成，屏幕刷新都会通过 fence 机制去锁住 buffer，多个 buffer 的存在，是为了缓解 fence 锁导致的等待问题。BlastBufferQueue 提供的接口设置 max buffer，目前，高端手机上配置的 max buffer 普遍在 6-8 个。


10. 调用android绘制三部曲（measure、layout和draw）的 performTraversals 是怎么触发的？

显示窗口时以及刷新 View 时（invalidate 和 requestLayout）都会调用到 schedualTraversals 方法，这里会 post 一个任务到主线程。当主线程回调到这个任务时，执行 performTraversals 方法。


11.  Android 的同步屏障和异步消息是什么，它们如何在渲染机制中发挥作用的？

Message 中通过 flag 成员中的一位标记 Message 是同步消息还是异步消息。

Message 的 target 成员通常不为 null，如果为 null，表示当前 Message 是一个同步屏障消息。

Looper 的主流程中会循环取 Message 处理，如果 Message 的 target 为 null，表示这是一个屏障消息，就会向后查询异步消息，优先处理异步消息，异步消息处理完了再处理同步消息。


App 需要绘制的时候，通常都会调用到 scheduleTraversals 方法：

```java
void scheduleTraversals() {
    if (!mTraversalScheduled) {
        mTraversalScheduled = true;
        //插入屏障
        mTraversalBarrier = mHandler.getLooper().getQueue().postSyncBarrier();
        //监听Vsync信号，然后发送异步消息 -> 执行绘制任务
        mChoreographer.postCallback(
                Choreographer.CALLBACK_TRAVERSAL, mTraversalRunnable, null);
        if (!mUnbufferedInputDispatch) {
            scheduleConsumeBatchedInput();
        }
        notifyRendererOfFramePending();
        pokeDrawLockIfNeeded();
    }
}
```

scheduleTraversals 方法中会向主线程 Looper 发送一个同步屏障消息，接着再向主线程 Looper 发送一个异步消息，该异步消息会被优先执行，异步消息的回调会调用到 performTravalsals 发起绘制过程。
