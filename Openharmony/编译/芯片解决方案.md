# OpenHarmony 基本概念和规则

## 子系统
Openharmony 中，子系统是一个逻辑概念，有对应的组件构成。包含了一组组件，提供特定的服务能力
## [[组件]]
- 对子系统的进一步拆分，可复用的软件单元，包含源码、配置文件、资源文件和编译脚本
- 可以独立构建，以二进制方式集成，具备独立验证能力的二进制单元

## 命名规则
为了实现芯片解决方案、产品解决方案与 openharmony 的解耦、可插拔。组件、芯片解决方案和产品解决方案的路径、目录树和配置文件会遵循一定的规则
* 组件源码路径为：`<领域>/<子系统>/<组件>`
* 芯片解决方案是一个特殊的组件，源码路径规则为：`<device>/<芯片解决方案厂商>/<开发板>`
* 产品解决方案是一个特殊的组件, 源码路径规则为:`vendor/<产品解决方案厂商>/<产品名称>`
# 芯片解决方案
- 芯片解决方案是指基于某款开发板的完整解决方案，包含驱动、设备侧接口适配、开发板 SDK 等
- 芯片解决方案是一个特殊的组件，源码路径为：`device/<芯片解决方案厂商>/<开发板>`
- 芯片解决方案组件会随产品选择的开发板默认编译
```
device
└── company
	└── board                  开发板名称
		├── BUILD.gn           编译脚本
		├── hals               OS南向接口适配
		├── linux              linux内核版本，可选
		|	└── config.gni     linux版本编译配置
		└── litos_a            liteos内核版本，可选
			└── config.gni     Liteos版本编译配置
```
> [!tips] config.gni 
> config.gni 为开发板编译的配置，编译时会采用该配置文件中的参数编译所有 OS 组件，编译阶段系统全局可见

```
kernel_type:              
kernel_verison:
board_cpu:
board_arch:              
board_toolchain:         开发板自定义的编译工具链名称，例如："gcc-arm-none-eabi",若为空，这使用默认ohos-clang
board_toolchain_prefix:  编译工具链前缀，例如："gcc-arm-none-eabi"
board_toolchain_type:    编译工具链类型：gcc clang
board_cflags:
board_cxx_flags:
board_ld_flags:          开发板配置链接选项
```
